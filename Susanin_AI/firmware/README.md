# Прошивка ESP32

| Папка | Что это | Состояние |
|---|---|---|
| [upstream/](upstream/DiffrentialControl_invert.ino) | исходник из набора BOTS без изменений (в нём SSID `bot1`) | этот вариант (с SSID `bot5`) стоит на роботе |
| [susanin_esp32/](susanin_esp32/susanin_esp32.ino) | тот же исходник с правками Ф1–Ф5 | **подготовлен, НЕ прошит, в Arduino IDE НЕ компилировался** |

Прошивать ESP32 — решение команды. Пока новая прошивка не залита, всё в репозитории
работает со старой; мост ROS 2 совместим с обеими.

## Что изменено

Распиновка, ШИМ (5 кГц, 8 бит), микшер `driveMix` и протокол WebSocket **не тронуты**.
Все правки в коде помечены `[Susanin F…]`.

| № | Правка | Где в скетче | Зачем |
|---|---|---|---|
| Ф1 | `COMMAND_TIMEOUT` 3000 → 500 мс | строка 44 | при пропаже связи робот останавливается через 0,5 с, а не через 3 с |
| Ф1 | страница повторяет последнюю команду джойстика каждые 100 мс, пока палец на экране | JS, строки 237–323 | без этого при таймауте 500 мс робот вставал бы, стоит задержать палец неподвижно. Заодно исчезает старая особенность: раньше робот сам останавливался через 3 с неподвижного удержания |
| Ф2 | при отключении любого WebSocket-клиента — `brake()` обоих моторов | `onEvent`, строка 471 | падение моста или закрытая вкладка браузера останавливают робота сразу |
| Ф3 | JSON разбирается из копии кадра с завершающим нулём; сообщения длиннее 127 байт и не-JSON игнорируются и **не перезапускают таймаут** | `handleWebSocketMessage`, строка 405 | исходный код читал память за концом кадра; мусор мог удерживать робота в движении |
| Ф4 | SSID `bot1` → `bot5` | строка 25 | чтобы после прошивки сеть называлась так же, как сейчас |
| Ф5 | блокировка моторов: по сообщению `{"lock":1}` от Raspberry Pi прошивка игнорирует **любые** команды движения, включая веб-джойстик, до `{"lock":0}`; без повторов блокировка сама снимается через 2 с | `handleWebSocketMessage`, `loop()` | кнопка СТОП на страничке оператора останавливает робота при любом способе управления. Со старой прошивкой СТОП действует только на команды от Raspberry Pi |
| — | при старте в Serial печатается строка версии | `setup()` | видно, какая прошивка залита |

Посмотреть все отличия:

```bash
git diff --no-index firmware/upstream/DiffrentialControl_invert.ino firmware/susanin_esp32/susanin_esp32.ino
```

Что сознательно **не** менялось: пароль точки доступа, поведение `fire` (силовой ключ не
отключается по таймауту — как и раньше), отсутствие плавного разгона (его делает узел
управления ROS 2; с телефона реверс по-прежнему мгновенный).

## Чем проверено и чем нет

| Проверка | Результат |
|---|---|
| Синтаксис C++: `g++ -fsyntax-only` с заглушками Arduino API (это не сборка под ESP32) | ошибок нет; исходный скетч на тех же заглушках проходит так же |
| Синтаксис JS страницы: `node --check` | ошибок нет |
| Страница в браузере (Chromium), сенсорные события сгенерированы скриптом, WebSocket подменён | удержание 1,05 с → 11 команд, пауза между ними не более 111 мс; после сдвига повторяется новая команда; после отпускания — `{"x":0,"y":0}`, повторы прекращаются |
| Модель поведения в эмуляторе ([test_firmware_variants.py](../ros2_ws/src/susanin_esp32_bridge/test/test_firmware_variants.py)) | старая прошивка после обрыва соединения продолжает ехать; новая останавливается сразу, а при «молчании» — через ~0,5 с; мост 20 Гц с новой прошивкой работает без ложных остановов |
| Компиляция в Arduino IDE (ядро ESP32 2.0.15, библиотеки BOTS) | **не выполнялась** — на ПК разработки нет Arduino IDE |
| Работа на реальной ESP32 | **не проверялась** |

Эмулятор написан по тем же исходникам, поэтому подтверждает логику, но не саму прошивку.

## Как прошить (когда решите)

Окружение — как в методичке BOTS2026: Arduino IDE, плата **ESP32 Dev Module**, ядро
esp32 by Espressif **2.0.15** (не 3.x), библиотеки из `libs/` набора BOTS, Arduino_JSON 0.1.0.

1. Робот на подставке, гусеницы в воздухе. Моторы во время прошивки не должны касаться пола.
2. Открыть `firmware/susanin_esp32/susanin_esp32.ino`.
3. Проверить строки 25–26: SSID и пароль те, что вам нужны.
4. Нажать **Verify** (галочка). Если компиляция не прошла — не прошивать, прислать текст ошибки.
5. Подключить ESP32 по USB, выбрать порт, нажать **Upload**, во время загрузки держать кнопку
   BOOT; после загрузки нажать RST.
6. Открыть Serial Monitor на 115200: первой строкой должно быть
   `susanin-esp32 1.2 (BOTS DiffrentialControl_invert + F1-F5)`.

## Проверка после прошивки (на подставке)

| № | Действие | Ожидание |
|---|---|---|
| 1 | Телефон: подключиться к `bot5`, открыть 192.168.4.1, вести джойстиком | управление как раньше |
| 2 | Держать джойстик неподвижно 10 с | гусеницы крутятся все 10 с (раньше останавливались через 3 с) |
| 3 | Отпустить джойстик | останов сразу |
| 4 | Во время движения выключить Wi-Fi на телефоне | останов не позже чем через ~0,5 с; в Serial — `disconnected` или `Command timeout!` |
| 5 | Во время движения закрыть вкладку браузера | останов сразу |
| 6 | `python scripts/esp32_probe.py --led-blink --seconds 10` | связь держится, переподключений 0 |
| 7 | Пункты 5.3 и 5.4 из [FIELD_TESTS.md](../docs/FIELD_TESTS.md) | останов ≤ 0,5 с вместо 3 с |
| 8 | Режим MANUAL, вести джойстиком, нажать СТОП на страничке `192.168.4.10:8080` | останов; джойстик не действует, пока не нажато «снять СТОП» |
| 9 | Нажать СТОП, затем выключить Raspberry Pi | через ~2 с джойстик снова управляет (блокировка не «залипает») |

## Откат

Прошить [upstream/DiffrentialControl_invert.ino](upstream/DiffrentialControl_invert.ino),
заменив в нём `bot1` на `bot5`. Это ровно то, что стоит на роботе сейчас.

## Побочные эффекты, о которых нужно знать

* Если к ESP32 подключены два управляющих клиента (телефон и мост ROS 2) и один из них
  отключается, робот на мгновение тормозит; следующий пакет от оставшегося клиента
  (через 50–100 мс) возобновляет движение.
* При плохом Wi-Fi (паузы больше 0,5 с) робот будет останавливаться — это и есть цель правки.
* Старые вкладки браузера со страницей прежней версии (без повтора команд) после прошивки
  нужно обновить, иначе робот будет вставать при неподвижном джойстике.
