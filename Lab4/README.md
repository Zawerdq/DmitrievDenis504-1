## Интерфейс subvector

```cpp
subvector<int> v;                       // пустой, рост ×2 (как у libstdc++)
subvector<int> w(Growth::add(100));     // рост +100
subvector<int> u(Growth::mul(1.5));     // рост ×1.5

bool push_back(const T& d);             // false, если память не выделилась
T    pop_back();                        // для пустого вектора — T{} (для int это 0)
bool resize(unsigned int new_capacity); // меняет ёмкость; если меньше size — обрезает данные
void shrink_to_fit();                   // capacity = size
void clear();                           // size = 0, capacity не меняется
```

В задании поле количества элементов называется то `size`, то `top`; это одно и то же поле `size`.
Обратите внимание: `resize` здесь меняет **ёмкость** (так сформулировано в задании), в отличие от
`std::vector::resize`, который меняет число элементов.

Дополнительно: деструктор, копирование (копия получает `capacity == size`, как у `std::vector`), перемещение,
`operator[]`, `get_size()`, `get_capacity()` и счётчики `stats()` — число перевыделений, перенесённых элементов
и пиковое число одновременно выделенных ячеек (старый + новый буфер в момент копирования).

## Сборка и запуск

```bash
./run_all.sh                   # всё сразу, ~15–25 минут из-за стратегий +10/+100
```

или по шагам:

```bash
g++ -std=c++17 -O0 -Wall -Wextra -fsanitize=address,undefined tests.cpp -o tests && ./tests
g++ -std=c++17 -O2 -Wall -Wextra bench.cpp -o bench
./bench capacity   data        # capacity std::vector от size + конструкторы
./bench strategies data        # +10, +100, ×1.5, ×2, std::vector, n = 0.1…10 млн
./bench factor     data        # время от множителя, n = 10⁷
./bench step       data        # время от прибавляемой константы, n = 10⁶ и 10⁷
python3 plot.py
```

Опция `--cap S` (по умолчанию 20): замер не запускается, если его прогноз по предыдущей точке
(для аддитивного роста время ∝ n²/step) больше S секунд. Такие точки записываются в CSV со статусом
`skipped_predicted_…` — это честно отмечено, а не выброшено. Без ограничения стратегия +10 на 10 млн
элементов работала бы часами.

## Методика

* Время — `std::chrono::steady_clock` (функция `get_time()` из задания), заполнение пустого контейнера
  n вызовами `push_back(i)`; в замер входит создание и заполнение, освобождение — нет.
* Перед каждой точкой короткий прогрев. Повторов: 7, если замер < 1 с; 3, если 1–5 с; 1, если дольше.
  На графиках — медиана и межквартильный размах.
* Результат заполнения используется (`g_sink`), чтобы компилятор не выбросил работу.
* Стратегии измеряются **вперемешку**: для каждого n порядок стратегий случайно перемешивается (seed фиксирован).
  Перед всеми замерами распределитель памяти прогревается выделением и освобождением блока 30 МБ.
  Без этого первая по порядку стратегия платила лишние page faults и выглядела в 3–4 раза медленнее
  (подробно — в отчёте, раздел 2).
* Замеряемые функции помечены `__attribute__((flatten))`, чтобы `push_back` и у `std::vector`, и у subvector
  был одинаково встроен в цикл.
* Счётчики перевыделений для `std::vector` собираются отдельным незамеряемым проходом по изменению `capacity()`.

## Форматы CSV

`data/strategies.csv`, `data/factor.csv`, `data/step.csv`:
`series,strategy,param,n,trial,seconds,reallocations,moved_elements,peak_elements,final_capacity,page_faults,status`

* `param` — множитель или прибавляемая константа; `n` — число добавленных элементов;
* `seconds` — время заполнения, с; `reallocations` — число выделений нового буфера;
* `moved_elements` — сколько элементов скопировано при перевыделениях (за всё заполнение);
* `peak_elements` — максимум ячеек `int`, выделенных одновременно (старый + новый буфер);
* `final_capacity` — ёмкость после заполнения;
* `page_faults` — число «мягких» page fault'ов процесса за время заполнения (`getrusage`, `ru_minflt`):
  сколько страниц памяти было впервые затронуто;
* `status` — `ok` или причина пропуска.

`data/std_capacity.csv` — `size,capacity` после каждого `push_back` до 1000 и после каждого изменения capacity
до 2·10⁶. `data/std_constructors.csv` — `size`/`capacity` после разных конструкторов и операций.
