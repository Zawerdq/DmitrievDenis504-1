# Автопилот: проезд участка после горки

Цель: после горки оператор включает автопилот, и робот сам доезжает до финиша —
по деревянной полосе, сквозь туннель и сквозь шар.

Состояние: код написан и проверен **в симуляторе на условной трассе**. На записи с
реальной трассы и на роботе не проверялось ничего; все цветовые пороги — заглушки.

## Как это работает

```
камера ─▶ зрение ─▶ автопилот ─▶ /cmd_vel ─▶ susanin_control ─▶ мост ─▶ ESP32
          (где полоса,   (шаги
           туннель, шар,  трассы)
           финиш)
```

**Зрение** ([vision.py](../ros2_ws/src/susanin_autopilot/susanin_autopilot/vision.py)).
Нижняя часть кадра режется на горизонтальные ленты, в каждой ищется самый широкий
участок «полосы». Середины участков дают смещение полосы от центра кадра (−1…+1).
Что считать полосой — параметр `track_mode`:

| `track_mode` | Маска | Когда использовать |
|---|---|---|
| `not_floor` | всё, что не синий пол и не тень | по умолчанию: нужен только цвет пола |
| `color` | цвет дерева | если в кадр попадает много постороннего |
| `line` | цвет нанесённой линии | если разрешат разметку |

**Автопилот** ([autopilot.py](../ros2_ws/src/susanin_autopilot/susanin_autopilot/autopilot.py))
идёт по шагам из параметра `route` и на каждом ждёт только одно следующее событие:

| Состояние | Что делает | Как заканчивается |
|---|---|---|
| `follow` | рулит пропорционально смещению полосы, в повороте сбавляет скорость | событие маршрута или потеря полосы |
| `tunnel` | едет прямо, кадр не использует | снова видна полоса и светло; иначе стоп по `tunnel_max_time` |
| `balloon` | едет прямо `balloon_time` секунд | по времени |
| `finishing` → `finished` | доезжает `finish_delay` и останавливается | — |
| `lost` | стоит и ждёт оператора | оператор снова включает AUTO |

Остановки без участия оператора: нет полосы дольше `lost_timeout`; нет кадров дольше
`frame_timeout`; туннель не кончился вовремя; заезд дольше `max_run_time`. Ниже по цепочке
действуют все прежние защиты (таймаут `/cmd_vel`, сторожевой таймер моста, прошивка).

## Режимы и оператор

Страничка оператора: `http://192.168.4.10:8080` (адрес Pi в сети `bot5`).

| Режим | Кто управляет | Мост |
|---|---|---|
| MANUAL | веб-джойстик ESP32 (`192.168.4.1`) | молчит |
| AUTO | автопилот (или teleop через ROS) | передаёт команды |

Порядок заезда: на телефоне две вкладки — джойстик и страничка оператора. До горки и на
горке — MANUAL. После горки, когда робот стоит ровно на полосе, — кнопка **AUTO**.
Перехват: кнопка **MANUAL** или **СТОП** (СТОП дополнительно требует «снять СТОП» перед
следующим AUTO). При запуске с автопилотом робот всегда стартует в MANUAL.

Ограничение: в режиме AUTO джойстик не перехватывает управление сам — сначала нужно
нажать MANUAL. Мгновенный перехват касанием джойстика потребует правки прошивки.

## Настройка по записи (делается один раз на трассе)

1. **Снять запись** — камера на роботе, робота ведут рукой или с джойстика:
   ```bash
   python scripts/record_camera.py --seconds 60 --name after_hill --note "высота 12 см, наклон 30"
   ```
2. **Измерить цвета** — координаты прямоугольника берутся в любом просмотрщике картинок:
   ```bash
   python scripts/vision_replay.py recordings/after_hill --sample 250,400,80,60
   ```
   Строку «с запасом для YAML» для области пола записать в `floor_hsv_low/high`
   (аналогично: шар → `balloon_hsv_*`, финишная метка → `finish_hsv_*`, тень туннеля →
   `dark_value`).
3. **Посмотреть, что видит алгоритм:**
   ```bash
   python scripts/vision_replay.py recordings/after_hill
   ```
   Результат — `recordings/after_hill_out/debug.avi`: зелёные точки — середины полосы,
   красная стрелка — куда рулить, в углу — состояние. Нужно добиться, чтобы полоса
   находилась на всех кадрах, где она есть, и стрелка смотрела туда, куда поехал бы человек.
4. **Задать маршрут.** Сначала `route: ["finish"]` (только полоса, остановка в её конце);
   после настройки цветов — `["tunnel", "balloon", "finish"]`.

Без записи посмотреть работу инструмента можно на условной трассе:
`python scripts/vision_replay.py --demo`.

## Камера

Симулятор и параметры по умолчанию рассчитаны на камеру на высоте около 12 см с
наклоном вниз около 30°: внизу кадра пол в 10–15 см перед роботом, вверху — около метра
впереди. При горизонтальной камере у самого пола полоса видна только вдалеке и на
повороте уходит из кадра. Точное положение выбирается по записям (шаг 1 — снять 2–3
варианта). Если камера видит выше горизонта, поднимите `roi_top`.

## Калибровка движения (на полу, после настройки зрения)

| Параметр | Как подобрать |
|---|---|
| `cruise_speed` | начать с 0.10; увеличивать, пока робот уверенно держит поворот |
| `steer_gain` | рыскает из стороны в сторону — уменьшить; не успевает в поворот — увеличить |
| `straight_trim` | в туннеле уводит влево — отрицательное значение, вправо — положительное |
| `tunnel_max_time`, `balloon_time` | измеренное время проезда × 1.5 |
| `min_duty`, `max_track_speed` (узел управления) | см. [SETUP.md](SETUP.md), раздел «Калибровка» |

## Что проверено

| Что | Как |
|---|---|
| Знаки руления, логика шагов, остановки | 40 тестов пакета, в т.ч. замкнутый контур в симуляторе |
| Параметры по умолчанию вместе с узлом управления и протоколом прошивки | `susanin_bringup/test/test_full_chain.py` |
| Узлы ROS, режимы, страничка оператора | `scripts/ros_smoke_test.sh` (эмулятор ESP32, нарисованные кадры) |
| Реальная камера, реальная трасса, робот | **нет** |

Симулятор ([sim.py](../ros2_ws/src/susanin_autopilot/susanin_autopilot/sim.py)) рисует
плоскую картинку с условными цветами. Он не моделирует блики, тени, фактуру дерева,
автоэкспозицию, вибрацию, проскальзывание гусениц и объёмные предметы (вход в туннель,
шар). Эти вещи проверяются только записью и заездами.
