# Лабораторная 3. Строки: цена передачи и копирования

Отчёт с гипотезами, графиками и выводами — в [REPORT.md](REPORT.md).

Владение памятью: исходные строки опыта A принадлежат `std::vector<std::string>` (Text) и `std::vector<Block>` (Block);
в опыте B — `std::unique_ptr<char[]>` в структуре `Sources`. `Text` ничего не освобождает. Копии из `clone_text`
освобождаются ровно один раз через `delete[]` тем кодом, который их создал (`release_copy` в `main.cpp`).

## Размер Block

Размер задаётся числом в `text.h`:

```cpp
#ifndef BLOCK_SIZE
#define BLOCK_SIZE 1024
#endif
struct Block { char data[BLOCK_SIZE]; };
```

Чтобы поменять размер, исправьте число и пересоберите. Скрипт делает то же самое через `-DBLOCK_SIZE=16/1024/16384`:
для каждого размера собираются отдельные исполняемые файлы. Длина `Text` в той же сборке равна `BLOCK_SIZE - 1`
(15, 1023, 16383), так что Block и Text сравниваются на одинаковой полезной длине.

## Сборка и запуск

Всё сразу (≈ 10 минут при настройках, которыми получены данные в `data/`):

```bash
./run_experiments.sh --trials 15 --target-ms 100   # так получены данные в data/
./run_experiments.sh                 # быстрее: по умолчанию --trials 9 --target-ms 80
./run_experiments.sh --seed 1 --trials 11 --target-ms 150   # свои параметры
./asm_check.sh                       # необязательно: ассемблер в asm/
```

Вручную, как в задании (без LTO; объявления в `text.h`, определения в `text.cpp`, вызовы и замеры в `main.cpp`):

```bash
g++ -std=c++17 -O0 -DBLOCK_SIZE=1024 tests.cpp text.cpp inputs.cpp -o tests && ./tests
J=-Wa,-mbranches-within-32B-boundaries   # см. «Флаг сборки» ниже
g++ -std=c++17 -O0 $J -DBLOCK_SIZE=1024 main.cpp text.cpp inputs.cpp -o research_debug
g++ -std=c++17 -O2 $J -DBLOCK_SIZE=1024 main.cpp text.cpp inputs.cpp -o research_opt
./research_debug A O0 data --scalar
./research_opt   A O2 data --scalar
./research_opt   B O2 data
python3 plot.py
```

### Флаг сборки `-Wa,-mbranches-within-32B-boundaries`

Процессор, на котором получены данные (Intel, модель 85 — Skylake-SP / Cascade Lake), подвержен ошибке JCC:
цикл, условный переход которого касается 32-байтной границы, исполняется заметно медленнее. Поэтому скорость
одного и того же машинного кода зависит от того, куда он случайно лёг в памяти. В контрольном опыте
(`./run_control_ref_ptr.sh`) `text_full_ref` и `text_full_ptr` с идентичным кодом в обычной сборке различались
в 1.7–2.4 раза, а с этим флагом — не больше чем на 2 %. Флаг передаётся ассемблеру, на семантику программы
не влияет и ничего не оптимизирует: ассемблер лишь вставляет выравнивающие префиксы и `nop`. Без него
сравнение способов передачи на такой машине измеряет расположение кода, а не способ передачи. На процессорах
без этой ошибки (AMD, Intel начиная с Ice Lake) флаг безвреден.

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `A` / `B` | — | опыт |
| `<opt_label>` | — | метка сборки в CSV (`O0`, `O2`) |
| `<out_dir>` | — | куда писать CSV |

## Исходные данные

Генератор `std::mt19937`, seed `20261023` (свой поток на каждую длину). Символы: ≈15 % пробелов, ≈3 % табуляций,
остальное — равномерно из видимых ASCII 33…126. Для каждой длины готовится 8 разных строк; они живут всё время опыта,
вызовы чередуют их по кругу (`g & 7`).

## Методика измерений (кратко)

* `std::chrono::steady_clock`, серия из G вызовов. G подбирается удвоением, пока серия не займёт ≥ target-ms
  (в данных — 100 мс), и
  фиксируется для всех сравниваемых вариантов условия; в CSV это `repeats`.
* Прогрев каждого варианта, затем `--trials` замеров (в данных — 15); порядок вариантов перемешивается в каждом замере.
* Результаты вызовов складываются в сумму, которая сохраняется после остановки таймера и проверяется на равенство
  между вариантами. Каждый результат отдельно проверяется до замеров.
* Вывод в файл — после всех замеров.
* В опыте B счётчики памяти собираются отдельным прогоном той же последовательности (`run_group<true>`);
  во временном прогоне они отключены на этапе компиляции (`run_group<false>`, `if constexpr`).

## Форматы CSV

`data/A_<opt>_<BLOCK_SIZE>.csv`, `data/B_O2.csv`:

`experiment,length,mode,work,repeats,uses,opt,trial,seconds,result`

* `experiment` — `scalar`, `Block`, `Text` или `copy` (опыт B);
* `length` — полезная длина в символах (для скаляра 0);
* `mode` — `value`/`ref`/`ptr` (A) или `borrow`/`copy_each`/`copy_once` (B);
* `work` — `short` (первый байт) или `full` (слова + сумма);
* `repeats` — G, число вызовов (A) или групп (B) в серии; `uses` — 1 в A и K в B;
* `opt` — сборка; `trial` — номер замера; `seconds` — время серии, с (17 значащих цифр);
* `result` — контрольная сумма результатов серии.

`data/B_counters.csv`: `length,repeats,uses,mode,allocations,copied_bytes,peak_extra_bytes`

* `allocations` — число вызовов `new[]` для исследуемых копий, шт.;
* `copied_bytes` — суммарно перенесено полезных байтов (без `\0`);
* `peak_extra_bytes` — максимум одновременно выделенных доп. буферов, байт (= элементов `char`, с `\0`;
  без служебных данных распределителя и стека; это **не** память процесса).

`data/B_counters_check.csv` — те же счётчики рядом с предсказанием по формулам и флагом совпадения.
`data/sizes_*.csv` — `sizeof` скаляра, `Block`, `Text`, указателя в каждой сборке.
